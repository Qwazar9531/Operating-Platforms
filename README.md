# Operating-Platforms
The Gaming Room is a client that wanted to expand its existing Android game, Draw It or Lose It, into a web based app that could support players across multiple operating platforms. The game needed to support multiple teams, unique game and team names, and a system capable of managing multiple users simultaneously. Throughout the project, I developed a software design document that evaluated different operating systems, system architectures, memory management, storage, and security considerations. I believe I did well in comparing the strengths and weaknesses of different platforms and explaining why a Linux based server environment would be a suitable choice for the application.

One of the most helpful aspects of creating the design document was being able to organize the software requirements before moving into development. Having a clear understanding of the application's structure made it easier to implement features such as the Singleton design pattern, which ensures that only one instance of the game service manages active games. If I could revise one part of my work, I would expand the security section to include more specific recommendations for protecting user information, managing authentication, and securing communication between clients and the server. This would provide the development team with more detailed guidance when implementing the application.

My approach to software design focused on understanding the client's requirements and determining which technologies could best support those needs. I considered factors such as scalability, performance, accessibility, and compatibility across different operating platforms. Understanding the user's needs is important because even a technically functional application can be unsuccessful if it does not provide a reliable and accessible experience. In future projects, I would continue using requirements analysis, design patterns, and comparisons of operating platforms to guide development decisions. I would also incorporate more testing and feedback throughout the design process to identify potential problems before they become difficult to correct.
